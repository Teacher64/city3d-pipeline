# City3D: устойчивость глобуса, покрытие LAS и постоянный кэш

Исправление от 19.10.2026 для присланного комплекта программы с установленным патчем глобуса и без патча преобразования CRS. Основной файл `city3d_pipeline_v5.py` остаётся прежним: заменяются известные модули глобуса, локальных журналов SQLite и страница глобуса. Неизвестные версии установщик отказывается изменять.

## Что исправлено

- Устранена воспроизведённая утечка открытых файлов: соединения SQLite закрываются после транзакций, включая ошибки и чтение кэша/MBTiles/журнала LAS. Закрываются также потоки ошибочных HTTP-ответов.
- Локальный HTTP-сервер ограничивает число одновременных обработчиков до 12, отключает зависшие клиенты и освобождает ресурсы при закрытии GUI. Обновления сцены не пересылают весь набор точек, пока сцена не изменилась.
- Пространственная выборка из LAS охватывает весь файл; прежняя выборка небольшими непрерывными участками давала полосы сканирования. Для LAZ быстрый обзор остаётся приближённым до полного прохода.
- Кнопка «Покрытие LAS по всем точкам» читает все точки последовательно и строит покрытие из занятых ячеек. Разрывы, отдельные участки и отверстия сохраняются в пределах выбранного шага. По умолчанию 5 м; оператор может менять шаг и бюджет отображаемых точек. Это приближение покрытия для просмотра, а не окончательная редактируемая граница обработки или юридическая граница.
- Полный проход выполняется в рабочем потоке, отменяется штатной кнопкой и сохраняет результат в `WORKSPACE/cache/las_coverage`. Первый проход по десяткам миллионов точек требует времени; повторный использует кэш, если исходный файл и параметры не изменились. Превышение лимита сложности выдаёт явную ошибку с предложением увеличить шаг.
- В GUI добавлена кнопка «Кэш подложек…». В браузере — блок «Постоянный кэш подложек». Показываются реальные число тайлов, размер, время записи, путь и разрешение сохранения для каждого сервиса.
- Локальная текстура NASA остаётся под картографическим слоем. Отсутствие тайла в офлайн-кэше показывает текстуру Земли, а не пустой глобус. Длинная запись WKT вынесена в подсказку.

## Установка

1. Закройте City3D и вкладки браузера со старым глобусом.
2. Распакуйте папку `city3d_globe_stability_patch` из архива в `/mnt/data_sda1/PR_3D_SPB/city3d-pipeline/`.
3. Выполните:

```bash
source /home/michel/city3d_env/bin/activate
cd /mnt/data_sda1/PR_3D_SPB/city3d-pipeline
python city3d_globe_stability_patch/fix_city3d_globe_stability_20261019.py
```

Команда проверяет версии и запускает проверки дескрипторов, покрытия, кэша и GUI в отдельных процессах. Код программы при этом не заменяется. Затем:

```bash
python city3d_globe_stability_patch/fix_city3d_globe_stability_20261019.py --apply
python city3d_pipeline_v5.py
```

Проверки перед установкой повторяются. При их ошибке изменение кода не выполняется. Установщик использует Python и библиотеки активного окружения; ничего не скачивает и не устанавливает через pip.

Резервная копия каждого заменяемого файла и основного скрипта создаётся в:

`/mnt/data_sda1/city3d-backups/city3d_globe_stability_<дата-время>`

Полный путь печатается после установки. Отчёт: `city3d_globe_stability_verification.json` в корне проекта; копия отчёта лежит в резервной копии. Повторный запуск установленного патча проверяет целостность и сообщает, что исправление уже установлено.

## Проверка в программе

1. На вкладке 1 добавьте и отметьте несколько LAS/LAZ, откройте глобус. Быстрый обзор появляется первым; флажок автоматического расчёта покрытия включён. Дождитесь сообщения «Покрытие по всем точкам: …» либо запустите расчёт кнопкой. Ошибки конкретных файлов доступны в подсказке строки состояния и в браузере.
2. Для более подробного покрытия выберите, например, 2 м и повторите расчёт. Меньший шаг увеличивает расход памяти и сложность границы. Исходные LAS не переписываются.
3. Выберите «OSM: интернет + кэш» и просмотрите район на нужных масштабах. Откройте «Кэш подложек…»: число сохранённых тайлов должно увеличиваться после успешных загрузок.
4. Переключитесь на «OSM: только кэш» и отключите интернет. Доступны ранее сохранённые тайлы на просмотренных масштабах. Непросмотренные участки не загружены автоматически. Для заранее подготовленной растровой карты страны/мира предусмотрено подключение MBTiles.

При текущем WORKSPACE ожидаемые пути:

- OSM: `/mnt/data_sda1/PR_3D_SPB/workspace/cache/osm/osm_cache.sqlite3`.
- Другие разрешённые к сохранению сервисы: `/mnt/data_sda1/PR_3D_SPB/workspace/cache/osm/services/<id_сервиса>/`.
- Ранее сохранённые тайлы общей папки читаются по прежним ключам.

Кэшируется только успешно полученное растровое содержимое и только когда адаптер/реестр разрешает сохранение. В окне явно видно, где оно выключено. Ноль тайлов означает отсутствие сохранённых карт; существование пустой SQLite-базы ещё не означает, что тайлы скачаны. Автоматического скачивания всего мира/страны из публичных геосервисов этот патч не добавляет.

Патч преобразования CRS пока не применяйте. Он был подготовлен под предыдущую версию модуля глобуса и после этого исправления потребует согласования. Совмещение CRS для просмотра продолжает работать; координаты исходных файлов не изменяются.

## Откат

Закройте программу и старые вкладки глобуса. Выполните команду, заменив `ПОЛНЫЙ_ПУТЬ_РЕЗЕРВНОЙ_КОПИИ` точным путём, напечатанным установщиком:

```bash
python city3d_globe_stability_patch/fix_city3d_globe_stability_20261019.py --restore ПОЛНЫЙ_ПУТЬ_РЕЗЕРВНОЙ_КОПИИ
```

Если после установки код редактировался, автоматический откат остановится, чтобы не затереть эти правки. Кэш и пространственные данные при откате сохраняются.

## Диагностика и выполненные проверки

После установки можно получить снимок открытых файлов работающей программы:

```bash
python city3d_fd_diagnostics.py --out city3d_fd_snapshot.json
```

Скрипт только читает `/proc`; лимиты системы не меняет. Необязательный `--details` добавляет пути файлов, `--pid ЧИСЛО` выбирает процесс.

Подробные результаты подготовки — в `VALIDATION_REPORT.json`. Нагрузочная проверка выполнялась с отключённой сборкой мусора и лимитом 96 дескрипторов только в тестовом дочернем процессе. После 1200 HTTP-запросов сохранялся один дескриптор слушающего сервера; после его закрытия число дескрипторов возвращалось к исходному. Отдельно проверены запись и офлайн-чтение тайлов, покрытие с отверстием и отдельным островом, рабочий поток вкладки загрузки, установка, повторная установка и откат.

Локальные проверки выполнены на Python 3.12.14 и Chromium 153. Установщик повторит встроенные проверки в вашем окружении Python 3.14.4. Тесты используют синтетические LAS и Qt offscreen; реальная видеокарта, сервер PostgreSQL, модели ИИ, сторонние ключи доступа и полный пользовательский архив этими проверками не испытывались.
