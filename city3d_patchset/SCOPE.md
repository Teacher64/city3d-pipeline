# Статус требований

| Требование | Поставлено | Что ещё не выполнено / условие |
|---|---|---|
| schema_refs и $9 | Исправлены причины в коде; тест libpq-параметров и SQL-патча | Нужна приёмка записи на вашей PostgreSQL |
| Несколько LAS, флажки, район | Рабочая подборка, источники, типы, UUID, название на всех вкладках | Разные CRS/point formats не нормализуются автоматически; большой набор требует RAM |
| Граница по точкам и мышь | Concave hull всех точек, Polygon/MultiPolygon, вершины, замена дуги, undo | Не точная граница съёмки при разрывах/дырах; нет Z-фильтра |
| Передача на следующие вкладки | M1 — общий LAS; M5 — список обрезанных LAS; датасет — кнопка добавления всей подборки | Старые SOR/voxel и M2/M3/M4/M6 ещё не полностью связаны с манифестом |
| Датасеты | Сохранение источников/классов/ID, групповое разбиение перекрытий, восстановление metadata | Нет универсального готового датасета для всех архитектур |
| Семантическая/геометрическая шина | Не разрушена существующая SemanticBus; добавлены пространственная редакция, происхождение и контекст | Сквозная проверка всех десяти вкладок и нейроадаптеров не завершена |
| ИИ-модели | Диагностика файлов, LFS, конфигураций и зависимостей | adapter_missing для чужих нейросетей пока не устранён; нужны конфиги/код/настоящие веса |
| Экспорт | Прямой LAS/LAZ/CSV и GeoJSON границы, явный выбор результата, provenance | Остальные старые форматы, объектное моделирование и SXF не исправлены полностью |
| OSM | Работающий код загрузки ways и обрезки, проверка с подменённым HTTP-ответом | Живая сеть не проверена; relations/крупные районы требуют доработки |
| SRTM | Добавлен отдельно обозначенный загрузчик DEM Skadi с несколькими источниками | Не является полноценным выполнением требования официального NASA SRTM |
| Номенклатура | Автопересечение со слоем ваших листов 1:50000 | Нужен заполненный topomap.topomaps; для LAS используется bbox |
| История | Автоиндекс диска, объединение с GUI истории, отдельный каталог в БД | Нельзя восстановить неизвестный район и доказать успех только по наличию файлов |
| Тесты и откат | Установщик, автоматические тесты, JSON-отчёт, резервные копии, откат | Не проведён полный GUI/GPU/SDK/PostGIS-прогон на сервере пользователя |

## Выявленные причины

Новый присланный главный файл отличается от предыдущего ровно подключением `city3d_tab1`. В нём сохранились отдельные источники истины: pcd в памяти, pcd_path, cropped/clean PLY, список датасета, реестр моделей и состояние PipelineRunner. Поэтому один checkbox без применённого рабочего набора не мог обеспечить участие всех облаков.

`ReferenceDBTab._download_task` вызывал отсутствующий внешний скрипт с фиксированным EPSG:32639 и не использовал kind для выбора нужного источника. `ExportTab._input_path` создавал промежуточный PLY; затем FormatExporter проверял принадлежность этого файла ResultSnapshot. Часть экспортеров пыталась использовать векторный ogr2ogr для облака LAS. Поэтому отключение одной проверки не исправило бы весь экспорт.

`HistoryTab.reload` показывал только PostgreSQL и не индексировал архив диска. Успех start_run также блокировался нетипизированным NULL-параметром.

`registry.py` прямо содержит adapter=None для ряда моделей. Наличие имени модели и большого .pth не заменяет архитектуру, точные входные каналы, preprocessing, label-map и inverse mapping. Снятие флага без этих условий создало бы ложную работоспособность. Найденные Cloud2BIM best.pth — Git LFS-указатели, что уже подтверждено вашим терминалом.
