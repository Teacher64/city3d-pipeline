# City3D — точечный патч первой вкладки, 1.0.0

Патч подготовлен для переданного нового `city3d_pipeline_v5(2).py` (внутренняя версия 7.5.0), в сравнении со старым `city3d_pipeline_v5 v7.3.1.py`. Работайте в существующем `~/city3d_env`. Не копируйте целиком другое виртуальное окружение и не заменяйте рабочие PyTorch/CUDA/NumPy без необходимости.

## Установка

Закройте City3D. Распакуйте архив, перейдите в его каталог `tab1_patch`.

```bash
source ~/city3d_env/bin/activate
python install_tab1.py --check-env
python install_tab1.py --target /mnt/data_sda1/city3d-release/city3d_pipeline_v5.py
python install_tab1.py --target /mnt/data_sda1/city3d-release/city3d_pipeline_v5.py --backup-dir /mnt/data_sda1/city3d-backups --apply
```

В `--target` укажите **фактически запускаемый** файл: указанный путь — пример на основании вашей папки release. Скрипт проверяет SHA256, а не имя файла. Если ваш рабочий код после копирования отличается от переданного, скрипт остановится без изменений; нужен этот изменённый файл для адаптации патча. Установщик намеренно не обходит эту проверку.

Без `--apply` выполняется только проверка. С `--apply` сохраняется исходный код, манифест отката и найденные DEB из каталога программы и его `dist/`; для DEB в другом месте добавьте `--deb /путь/пакет.deb`. Само окружение, веса, исходные облака и другие модули backend не перезаписываются. В программе добавляются две строки подключения, рядом появляется `city3d_tab1/`. Старый код вкладки остаётся внутри исходника для отката. Повторная установка того же патча безопасна.

Если отсутствуют зависимости, устанавливайте только отсутствующие пакеты в активное окружение. Для патча нужны `laspy>=2`, `pyproj>=3.4`, `numpy`, `PyQt5`; LAZ требует доступного backend `lazrs` или `laszip`. Для PostgreSQL нужен уже используемый `psycopg` либо `psycopg2`. Автоматического обновления библиотек установщик не делает.

Запуск программы после установки — вашей обычной командой, из старого окружения.

## Работа на первой вкладке

1. «Добавить файлы» принимает несколько файлов. «Добавить папку» обходит поддержанные форматы, при необходимости с подпапками. Искусственного лимита числа файлов нет; таблица и реестр метаданных всё равно занимают память и диск.
2. LAS/LAZ читаются блоками по 500 000 точек. Считаются все фактические ID классов, включая пользовательские, и флаги точек. Классы 0/1 не выдаются за выполненную тематическую классификацию. Файл не переклассифицируется и не перезаписывается.
3. CRS читается из WKT/GeoTIFF LAS и соседних `.prj`/`.wkt`. При противоречии либо повреждённых метаданных требуется решение оператора. Угадывания МСК по величине координат нет. `.PRJ` в верхнем регистре следует переименовать в `.prj` в Linux.
4. Выделите один или несколько файлов, нажмите существующую кнопку выбора CRS. Ищите в EPSG/ESRI либо добавьте своё определение. «Новая МСК» очищает поля; задайте название, источник параметров и полное WKT/PROJJSON либо код CRS, затем «Сохранить / обновить МСК». Определение можно импортировать из PRJ/WKT/JSON. Выбор сохранённой пользовательской строки позволяет редактировать или удалить её. EPSG/ESRI не меняются: их определение можно сохранить отдельной пользовательской записью.
5. Нажатие OK назначает CRS выделенным файлам после подтверждения и повторно индексирует их. Координаты и высоты исходника не меняются. Сохраняется снимок определения и сведения о его источнике/версии. Редактирование справочника не меняет ранее назначенные определения автоматически.
6. «Загрузить выбранный файл полностью» передаёт **все точки одного активного облака**, а не прореженный предпросмотр, действующим вкладкам. Остальная подборка остаётся в реестре. Полная загрузка крупного файла по-прежнему требует RAM; пакетная обработка всех файлов в M1 этим патчем не реализуется. Отмена полной загрузки срабатывает после возврата штатного загрузчика; индексация отменяется между блоками.
7. «Записать реестр в БД» показывает целевую БД из раздела настроек и создаёт дополнительные таблицы в ней, после чего записывает метаданные. При отсутствии БД локальный реестр сохраняется. Повторная отправка одной записи не создаёт дубликатов; повторная индексация создаёт новую историю наблюдения.

Пользовательский справочник: `~/.config/city3d/custom_crs.json`; резервные версии: `~/.config/city3d/custom_crs_history/`. Каталог сохраняет введённые оператором определения, но не подтверждает их геодезическую точность: проверяйте по контрольным точкам. Работайте с редактированием справочника в одном экземпляре City3D.

Локальный реестр и история: `~/.local/share/city3d/tab1_inventory.sqlite3`. «Экспорт реестра JSON» позволяет передать текущие метаданные без БД. Этот экспорт не заменяет вкладку 6.

## Схема PostgreSQL

Используется структура предоставленного `метаданные.sql`: схема `als`, существующая таблица `als.als` сохраняется. В ней обязательны сведения о владельце, исполнителе, договоре, лазере, годе и классификации. Их нельзя достоверно получить из каждого LAS, поэтому автоматическая запись туда с фиктивными значениями исключена.

Создаются:

- `als.city3d_input_files`: UUID содержимого, SHA256, размер;
- `als.city3d_input_inspections`: путь, время, число точек, гистограмма классов, CRS WKT, границы, геометрия в WGS84, происхождение и полный JSON метаданных;
- индексы по файлу, времени и GiST по геометрии.

`legacy_als_id` — необязательная связь с деловой записью `als.als.id`; в этом патче это поле не заполняется автоматически и не имеет внешнего ключа. Не путайте её справочник `classifi` с кодами классов ASPRS.

Нужны существующая БД, PostGIS в схеме public и права CREATE в `als`. Патч не запускает ваш SQL-дамп, не создаёт сервер БД и не удаляет таблицы. Ошибка транзакции откатывает всю отправку; локальные данные остаются.

**Контур сейчас — приблизительный охватывающий прямоугольник (bbox), рассчитанный по всем точкам.** Это не точная граница фактического покрытия, не вогнутая оболочка и не площадь обработанной территории. Метод явно сохранён в БД. Для неизвестного CRS, недоступных преобразований, вырожденной площади и пересечения антимеридиана WGS84-геометрия не создаётся. Географический охват рассчитывается только без ballpark-преобразований и при доступности лучшего преобразования PROJ; Z не преобразуется.

Статус после добавления — `indexed`, а не `processed`. Связывание геометрии **успешной обработки** с `PipelineRunner` и результатом M1 — следующий патч; этот выпуск не приписывает обработку просто прочитанным файлам.

## Границы совместимости

Произвольные МСК без EPSG уже сохраняются, редактируются, назначаются и используются для расчёта каталожного охвата, если PROJ располагает достаточными параметрами. Однако старые вкладки передают CRS преимущественно через числовой EPSG. Для таких МСК полная сквозная поддержка экспорта/перепроецирования ещё требует замены этого контракта на WKT/PROJJSON. Патч показывает это предупреждение и передаёт дополнительный `main_window.input_crs_wkt`; он не выдаёт фиктивный EPSG.

Настройки вертикальной системы и поправки высоты сохранены из исходного GUI; настоящая вертикальная трансформация этим патчем не реализуется. Неразмеченные файлы не становятся эталонами автоматически. ИИ-модели, веса и качество классификации этот патч не меняет.

## Откат

Установщик напечатает точный путь к `restore.json`:

```bash
source ~/city3d_env/bin/activate
python install_tab1.py --restore /mnt/data_sda1/city3d-backups/tab1_ДАТА/restore.json
```

Если после установки исходник или модули изменены, автоматический откат остановится, чтобы не потерять правки. Успешный откат восстанавливает исходник и переносит модули патча в резервную папку; реестры, пользовательские МСК и БД сохраняются.

## Проверка у оператора

Проверьте на копиях рабочих данных: LAS с известным CRS, LAS без CRS, LAZ, файл с готовой классификацией, папку с несколькими облаками. После выбора другого активного файла убедитесь в очистке путей предобработки/обрезки. Отдельно сохраните МСК, измените её, перезапустите приложение и проверьте историю. Затем отправьте реестр в тестовую БД и повторите отправку: число записей не должно увеличиться без повторной индексации.

Программные тесты: `PYTHONPATH=. QT_QPA_PLATFORM=offscreen python -m pytest tests -q`. Для тестов дополнительно нужны `pytest`, `pglast`; интеграционный тест установщика использует переданный исходник из соседнего `upload/` и будет пропущен, если его нет. Результаты и ограничения проверки — в `TEST_REPORT.md`.
