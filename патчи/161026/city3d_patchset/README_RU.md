## Установка в вашем окружении

Закройте City3D. Распакуйте архив и перейдите в папку `city3d_patchset`.

```bash
source /home/michel/city3d_env/bin/activate
python apply_patchset.py --patch 01
python apply_patchset.py --patch 01 --apply
python /mnt/data_sda1/PR_3D_SPB/city3d-pipeline/city3d_pipeline_v5.py
```

Без `--apply` — только проверка. Целевой путь по умолчанию уже ваш. Для другой копии задайте `--target /полный/путь/city3d_pipeline_v5.py`. Не копируйте файл из `fixtures` поверх рабочего: он нужен только тестам.

**01 — БД и журнал:** устраняет обе ошибки из журнала и переводит сообщения LogWidget в основной поток Qt. Сначала проверьте «Записать реестр в БД» на одном LAS. Патч не создаёт отсутствующие старые таблицы `history.training_runs`: исправление SQL не заменяет их миграцию.

После проверки 01, снова закройте приложение:

```bash
python apply_patchset.py --patch 02 --apply
```

**02 включает 01**, добавляет общий район, флажки файлов, тип съёмки для каждого файла, рабочую подборку LAS, полигональную границу с редактором, передачу подборки в M1/M5 и добавление района в датасет.

Затем при необходимости:

```bash
python apply_patchset.py --patch 03 --apply
```

**03 включает 01 и 02**, добавляет прямой экспорт LAS/LAZ/CSV/границы GeoJSON, индексирование дискового архива, скачивание OSM ways и DEM Skadi по границе, определение листов по вашему векторному слою `topomap.topomaps`.

Каждый запуск с `--apply` сохраняет затрагиваемые файлы в `/mnt/data_sda1/city3d-backups/city3d_fixset_ДАТА/`. Там находятся `manifest.json` и `verification.json`. Модули устанавливаются до подключения в основном файле, чтобы не повторить ошибку `No module named city3d_tab1`. Существующие файлы старого пакета `city3d_tab1` не перезаписываются; отсутствующие добавляются из комплекта. Исходные LAS, модели, окружение и существующие БД не удаляются.

Проверка SHA256 допускает исходный присланный файл и последующие редакции этого установщика. При сторонних изменениях основного кода установка остановится. Архивы DEB этим установщиком не изменяются и новая сборка DEB не выполняется.

## Зависимости и проверка

Для 02/03 нужны `laspy`, `numpy`, `pyproj`, PyQt5 и **Shapely >=2 / GEOS >=3.11**. Для редактора мышью нужен `matplotlib`; для LAZ — backend `lazrs`/LASzip; для DEM — `rasterio`; для тестов — `pytest` и `psycopg`. Установщик не обновляет окружение. При недостающей библиотеке установите только её в `city3d_env`, не заменяя рабочий PyTorch/CUDA.

```bash
python verify_patchset.py --report verification_report.json
```

Проверка выполняет синтетические тесты и сохраняет JSON с результатами и версиями библиотек. Она не открывает весь City3D и не доказывает работоспособность всех ИИ-моделей.

Для дополнительной **проверки чтения** действующей PostgreSQL:

```bash
python verify_patchset.py --live-db --report verification_with_db.json
```

Этот режим берёт явный раздел `database` из `~/.config/city3d/settings.json`; если раздела нет, соединение не угадывается. В нём нет создания/изменения таблиц. Параметры БД и пароли не включаются в отчёт. Само создание таблиц проверяется при работе кнопок GUI на вашей БД.

## Работа с подборкой и районом

1. Добавьте LAS/LAZ в таблицу. Поставьте флажки напротив нужных файлов. «Отметить все»/«Снять все» и прокрутка таблицы позволяют работать с большим списком.
2. В последнем столбце задайте вид съёмки отдельно для каждого файла: ALS, MLS, TLS и т. д.
3. Введите имя района. «Сохранить выбор / название» сохраняет черновик; **рабочая редакция изменится только после «Применить отмеченные LAS»**.
4. Подтвердите согласованность системы высот. Исходные LAS не перезаписываются. Все отмеченные файлы входят в `workset.las`; рядом сохраняются обрезанные копии каждого источника и `project.json`.
5. Название и номер редакции видны сверху каждой вкладки. После перезапуска кнопка «Восстановить последний рабочий район» проверяет хеш рабочего LAS и загружает его.
6. «Записать реестр в БД» сохраняет каталог файлов и район в `als.city3d_project_revisions`. Геометрия в этой таблице находится в исходном CRS (SRID=0), а точное WKT записано отдельно. Не интерпретируйте её как EPSG:4326. Рядом с рабочими файлами есть `boundary.geojson` в WGS84, если доступно корректное преобразование.

Совпадающие по содержимому файлы не разрешены в одной подборке: это защита от двойного включения копии. Разные съёмки с перекрытием сохраняются целиком, без автоматического удаления точек. В LAS добавлены `c3_source_index` и `c3_original_index`; связь с исходным файлом хранится в project.json. Тип съёмки сохраняется для каждого источника. Для смешанной подборки старый общий пресет получает `unknown`; автоматическая настройка отдельной модели под каждый тип ещё не реализована.

**Ограничения объединения:** нужны одинаковая подтверждённая CRS, XY в метрах и совместимые point format/Extra Bytes. Разные масштабы и offsets поддержаны с проверкой int32. Разные форматы точек, waveform LAS и преобразование между разными CRS намеренно не объединяются с потерей информации. В таком случае выберите совместимую группу. Z не преобразуется. VLR каждого источника сохраняются в его отдельном обрезанном LAS; общий LAS наследует общие метаданные первого источника.

Построение границы использует все XY-точки каждого файла и требует RAM. Полная загрузка объединённого LAS тоже требует памяти. Это не out-of-core визуализатор для неограниченного объёма.

## Граница / BBOX

В присланном коде BBOX — третий экран после загрузки и предобработки. Патч находит **класс BoundingBoxTab**, не меняет нумерацию вкладок.

Граница — объединение concave hull по каждому выбранному LAS; отдельные части района сохраняются. В отличие от bbox, это оболочка по координатам точек, но она всё равно оценивает покрытие и может соединять разрывы внутри одной съёмки. Параметр 0…1 регулирует подробность; внутренние дыры автоматически не выделяются.

Редактор: перетаскивайте вершины левой кнопкой. Для изменения участка выберите «Заменить участок»: первая вершина → вторая вершина того же кольца → ребро нужной дуги между ними. Затем кликами задавайте новые вершины; предварительная линия следует курсору. Завершение — правая кнопка и меню, двойной правый клик или кнопка завершения. Есть отмена последней правки. Самопересекающаяся граница не принимается.

«Применить границу» создаёт новую редакцию и обрезает все отмеченные LAS. Точки на границе включаются; исходные ID и классы сохраняются. Для разных полигонов/колец редактирование выполняется отдельно. Прежний редактор числового Z-диапазона этим экраном заменён; фильтра Z в новом редакторе пока нет.

## Датасет и обучение

На вкладке датасета добавлена кнопка «Добавить все LAS текущего района». Она добавляет обрезанные источники с уникальными именами и сохраняет project_revisions в metadata.json. Метки автоматически не объявляются проверенными эталонами.

Разбиение LAS выполняется по связанным группам пересекающихся XY-bbox, чтобы перекрывающиеся съёмки не попали одновременно в train и validation/test. Требуются минимум три независимые группы и общий CRS. При существующем содержимом processed необходимо выбрать новую папку датасета — новые части не смешиваются со старым разбиением. Аугментация остаётся только для train.

M1 получает общий workset; список M5 заполняется всеми обрезанными источниками. Растры/маски/DEM/векторы методов M2/M3/M4/M6 не становятся автоматически корректными обучающими примерами из LAS. Формирование специальных датасетов под каждую нейросеть этим выпуском не завершено.

Существующий SemanticBus не заменён. Сохраняются классы LAS, точечные ID и происхождение; для обычных прогонов и PipelineComposer пишется project_context.json. Это основание общего состояния, но не полная проверка семантического объединения всех методов. Предобработка SOR/voxel старого кода ещё не переведена на новый манифест — не считайте её изменение предпросмотра изменением рабочего LAS для M1.

## Экспорт и история

На вкладке экспорта используйте новые кнопки вверху. «Текущий район» экспортирует применённую редакцию; «Выбранный LAS-результат» позволяет явно выбрать классифицированный файл. Поддержаны LAS, LAZ, CSV точек/классов/ID и GeoJSON границы. Успех подтверждается созданным файлом и provenance.json. Существующий файл не перезаписывается. Высоты и CRS облака при прямом экспорте остаются исходными; настройки старых объектных экспортеров на него не влияют.

Старые USD/OBJ/IFC/CityGML/DXF/PostGIS-экспортеры **не объявлены исправленными**. Не формируется ложная модель здания из convex hull всего района. SXF не реализован без установленного SDK Панорамы и RSC.

История при открытии вкладки объединяет записи БД и каталоги training_output. Файлы тайлов не считаются отдельными обучениями. Индекс сохраняется в workspace/archive_history.json, при доступной БД — в отдельной таблице `<schema_history>.city3d_archive_catalog`. Старые записи training_runs не переписываются. Из snapshot извлекается заявленный статус с префиксом `snapshot_`, без заявления о повторной проверке всех хешей. Неизвестные район/номенклатура остаются неизвестными. Имена старых папок не доказывают качество и успех обучения.

## Эталоны, OSM, DEM и номенклатура

Новая загрузка не зависит от ~/tools/setup_references_v5.py и не подставляет EPSG:32639. Используется активная граница с проверенным преобразованием в WGS84.

OSM: здания, дороги, водотоки типа way через Overpass, обрезанные по границе. Сохраняются OSM ID, название района, источник и ODbL. Multipolygon relations этим загрузчиком ещё не импортируются. Размер запроса ограничен районом до 0.25° по каждой оси; превышение даёт явное сообщение, а не неполные данные.

DEM: кнопка честно переименована в **DEM Skadi (несколько источников)**. Это Mapzen Terrain Tiles, не обещание чистого NASA SRTM. Загружаются до 16 HGT-тайлов, собираются и маскируются границей в GeoTIFF. Подключение отдельного официального NASA SRTM с нужной авторизацией остаётся отдельной задачей. Файлы зарегистрированы в дополнительной локальной SQLite-таблице city3d_external_references, а не в таблице облаков. Перенос самих векторных/растровых данных этих эталонов в PostGIS ещё не реализован.

После «Дата» добавлен столбец листов 1:50000. Автоматический поиск использует пересечение с вашим слоем topomap.topomaps при scale=50000; если слоя/покрытия/CRS нет, это явно указано. Непроверенная формула номенклатуры не используется. Для LAS-эталонов поиск пока опирается на bbox заголовка; для GeoJSON — геометрию, для GeoTIFF — границы растра. Несколько листов отображаются списком. Для новых районов найденные листы включаются в манифест, границу GeoJSON и контекст новых обучений.
